# 脅威モデル：CT ログによるフィッシングドメイン監視

## 1. 目的と範囲

Certificate Transparency（CT）ログを定期的に検索し、監視対象ブランドに似たドメインの証明書を検知する。検知したドメインについて WHOIS（RDAP）と DNS で付加情報を取得し、通知する。実行基盤は GitHub Actions とする。

範囲外：検知したドメインの Web ページへのアクセス、テイクダウン依頼などの対処。

## 2. 前提

- 練習段階の監視対象は、公開ブランド（PayPal）とする
- 業務への転用を想定し、コード・設定・出力の3層を分離する
  - コード：public リポジトリで管理する。ブランド名を含めない
  - 設定（監視キーワード、通知先）：コードの外から渡す
  - 出力・状態（検知結果、どこまで見たか）：機密として扱う
- 練習段階でも、検知結果は本番と同じく機密として扱う

## 3. 資産

| 資産 | 守りたい性質 |
|---|---|
| 監視キーワード | 機密性（本番時） |
| 検知結果 | 機密性 |
| 状態（どこまで見たか、通知済みか） | 完全性 |
| 通知先の資格情報 | 機密性 |
| ワークフローと依存関係 | 完全性 |
| 監視が動き続けること | 可用性 |

## 4. 信頼境界

信頼できない入力：

- CT ログ上のドメイン名・証明書の項目（攻撃者が自由に決めて登録した文字列）
- crt.sh などのデータ源の応答（形式や内容が予告なく変わりうる）
- WHOIS／DNS の応答（攻撃者が管理するサーバーが返しうる）
- PR に含まれるコードとワークフロー

## 5. 脅威と対策

| ID | 脅威 | 対策 | 状態 |
|---|---|---|---|
| T1 | 検知結果・キーワードが Actions のログや artifact から漏れる | 検知結果をログ・artifact に出力しない。結果は通知でのみ渡す | 予定 |
| T2 | 攻撃者が決めた文字列によるインジェクション（シェル、ワークフローコマンド、通知の書式） | 取り込み時にドメイン名の形式を検証し、外れたものは捨てる。シェルを経由せずに外部コマンドを呼ぶ。外部の値を `run:` に `${{ }}` で埋め込まない | 予定 |
| T3 | 依存パッケージや Action の改ざん（supply chain） | Action のコミットハッシュ固定、ハッシュ付き requirements.txt、Dependabot | 予定 |
| T4 | PR の中で検査やワークフローを骨抜きにされる | ruleset（PR 必須、必須チェック、force push 禁止）、差分のレビュー | 予定 |
| T5 | 状態の改ざん・消失による見逃しや重複通知 | 保存先と更新方法を設計する（ruleset との整合が課題） | 設計中 |
| T6 | データ源の停止・制限で、検知漏れが「検知なし」に見える | 取得の失敗と「該当なし」を区別し、失敗はジョブの失敗として扱う（crt.sh は制限時に空の結果を返すことがある） | 予定 |
| T7 | 定期実行が遅延・停止し、監視が黙って止まる | 実行の成否とは別に、「一定時間実行がないこと」を検知する仕組みを置く | 予定 |
| T8 | 調査行為が攻撃者に観測される | 調査は WHOIS（RDAP）と DNS に限定し、Web ページにはアクセスしない | 予定 |
| T9 | 通知先の資格情報の漏えい | Secret に保存し、必要なジョブにだけ渡す | 予定 |

## 6. 既知の限界

| ID | 限界 | 影響 |
|---|---|---|
| L1 | 検索型のデータ源では、検索文字列を含まない変形（typo、よく似た文字への置き換え）を検知できない | 変形によるフィッシングを見逃す |
| L2 | crt.sh の CT ログ取り込みが遅れることがある | crt.sh で見えないことは、未発行を意味しない |
| L3 | crt.sh の検索結果は約999件で打ち切られる | 件数の多いキーワードで取りこぼす |
| L4 | 一人運用のため、作成者と承認者が同一人物 | 職務分掌が成立しない |
